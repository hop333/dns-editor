# Безопасность

DNS Editor управляет authoritative zone-файлами DNS. Относитесь к панели как к production-инфраструктуре: компрометация панели означает возможность менять DNS-записи доменов.

## Пароль администратора и секреты

При установке через `deploy/install.sh` пароль администратора и `SECRET_KEY`
генерируются автоматически и сохраняются в `/opt/dns-editor/.env`. Файл получает
права `600`, поэтому читать его должен только root.

Посмотреть сгенерированный пароль можно на сервере:

```bash
sudo grep ADMIN_PASSWORD /opt/dns-editor/.env
```

Если `.env` создаётся вручную из `deploy/docker.env.example`, пароль и
`SECRET_KEY` нужно заменить самостоятельно до запуска.

Никогда не публикуйте `.env`, `config/rndc.key` и DNSSEC-ключи из `zones/keys`.

## Правила для production

- Не публикуйте backend-порт `8000` в интернет.
- Не публикуйте frontend-порт `3000` напрямую, если используется Caddy или nginx.
- Открывайте API только через `/api` на том же домене, где находится панель.
- Используйте HTTPS для любого публичного развёртывания.
- Храните реальные секреты только в `.env`.
- После установки сохраните пароль администратора в надёжном месте.
- Держите firewall строгим: обычно достаточно портов `22`, `53`, `80` и `443`.
- Не размещайте панель на основном публичном домене сайта. Используйте отдельный
  поддомен, например `dns.example.com` или `panel.example.com`.

## DNSSEC

Включение DNSSEC в панели подписывает зону в BIND и показывает DS-записи. Полная цепочка доверия появляется только после того, как DS-запись добавлена у регистратора домена.

Если нужно откатиться, сначала отключите DNSSEC в панели, затем удалите DS-записи у регистратора.
