# Делегирование домена на свои NS

Этот документ описывает, как перевести домен на DNS-сервер, который управляется через DNS Editor.

Пример ниже использует домен `example.com` и VPS с IP `203.0.113.10`. Для реального проекта замените их на свой домен и IP сервера.

## Общая схема

На одном VPS могут работать:

- BIND на порту `53` - authoritative DNS-сервер;
- DNS Editor на поддомене `dns.example.com`;
- публичный сайт на `example.com`;
- nameserver-имена `ns1.example.com` и `ns2.example.com`.

Типовая схема:

```text
example.com       -> публичный сайт
dns.example.com   -> панель DNS Editor
ns1.example.com   -> IP VPS
ns2.example.com   -> IP VPS
```

`ns1` и `ns2` могут указывать на один и тот же IP. Для учебного проекта и небольшого self-hosted развёртывания это допустимо, хотя в production лучше иметь два независимых DNS-сервера.

## 1. Подготовить зону в DNS Editor

В панели создайте или откройте зону `example.com`.

Минимальный набор записей:

```text
@     NS    ns1.example.com.
@     NS    ns2.example.com.
ns1   A     203.0.113.10
ns2   A     203.0.113.10
@     A     203.0.113.10
www   A     203.0.113.10
dns   A     203.0.113.10
```

После изменения записей нажмите сохранение зоны и перезагрузите BIND через интерфейс.

## 2. Проверить, что BIND отвечает

На сервере:

```bash
dig @127.0.0.1 example.com A +short
dig @127.0.0.1 ns1.example.com A +short
dig @127.0.0.1 example.com NS +short
```

С внешней машины или через публичный resolver:

```bash
dig @203.0.113.10 example.com A +short
dig @203.0.113.10 example.com NS +short
```

Если прямой запрос `@203.0.113.10` с домашнего компьютера даёт timeout, проверьте с VPS или через другой интернет-канал. Некоторые провайдеры и локальные сети фильтруют DNS-запросы.

## 3. Добавить glue-записи у регистратора

Если nameserver'ы находятся внутри того же домена, например `ns1.example.com` и `ns2.example.com`, регистратору нужны glue-записи. Это A-записи nameserver'ов на уровне регистратора.

В панели регистратора найдите раздел с одним из названий:

- `Glue records`;
- `Child nameservers`;
- `Host records`;
- `Зарегистрировать DNS-сервер`;
- `Создать NS`;
- `IP-адреса DNS-серверов`.

Добавьте:

```text
ns1.example.com -> 203.0.113.10
ns2.example.com -> 203.0.113.10
```

У разных регистраторов интерфейс называется по-разному. В REG.RU это обычно делается в управлении доменом, отдельно от обычной DNS-зоны.

## 4. Сменить NS у домена

В карточке домена у регистратора замените текущие NS на свои:

```text
ns1.example.com
ns2.example.com
```

После сохранения начнётся обновление делегирования. Обычно оно занимает от нескольких минут до нескольких часов, но иногда может растянуться до суток из-за кешей.

## 5. Проверить делегирование

Проверка NS:

```bash
dig example.com NS +short
```

Проверка A-записи через обычный resolver:

```bash
dig example.com A +short
```

Проверка трассировки:

```bash
dig +trace example.com NS
```

Если всё настроено правильно, в ответе должны появиться `ns1.example.com` и `ns2.example.com`, а записи зоны должны отдаваться вашим BIND.

## Частые проблемы

| Проблема | Причина | Что сделать |
|---|---|---|
| Регистратор не принимает `ns1.example.com` | Нет glue-записи | Добавить IP для `ns1`/`ns2` у регистратора |
| `ns2.example.com` возвращает NXDOMAIN | Создан только `ns1` | Добавить A-запись для `ns2` |
| Домен всё ещё смотрит на старый IP | NS ещё не сменились или кешируются | Проверить NS в карточке домена и подождать обновления |
| Запись создана в UI, но не видна в DNS | Зона не сохранена или BIND не перезагружен | Сохранить зону и выполнить reload |
| Запрос `dig @IP` timeout | Порт `53` закрыт или фильтруется сетью | Проверить firewall/VPS-панель и `dig @127.0.0.1` на сервере |

## DNSSEC

DNSSEC включайте только после того, как обычное делегирование уже работает.

Порядок:

1. Включить DNSSEC в панели.
2. Перезагрузить BIND.
3. Скопировать DS-запись из панели.
4. Добавить DS-запись у регистратора.

Если нужно откатиться, сначала удалите DS-запись у регистратора, затем отключите DNSSEC в панели.
